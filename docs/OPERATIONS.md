# 操作手册

这份文档讲**怎么用**：界面上每个控件在哪、点了会发生什么、哪些操作有前提。它不解释设计取舍
（那是 [DESIGN.md](DESIGN.md)），也不讲第一次怎么装（那是 [QUICKSTART.md](QUICKSTART.md)）。

文中的「面板」指侧栏那个「待办」入口打开的主界面。所有操作都在这个面板里完成，除了标注为
「让 Agent 做」的那几条——那几条是对话里的工具调用。

---

## 1. 面板结构

从上到下五层，每层的职责不要混：

```
┌─ 标题行 ────────────── 全局待办 · 副标题 · 齿轮(设置) · ＋添加 · ⋮(更多操作)
├─ 上下文行 ──────────── 工作目录 · 交给:<对话名> · 上下文   [手机: 收进设置]
├─ 筛选行 ────────────── 全部 未完成 进行中 已完成 逾期 [归档] [收件箱] [待确认] [陈旧] [稍后]
│                       · 搜索框 · 工作区/时间/待办等级 · 自动获取开关
├─ 列表区 ────────────── 按当前分组维度折叠的分组 + 每组下的行
└─ 浮层 ──────────────── 设置卡 · 周报卡 · 快捷键卡 · 交给哪对话选择框 · 提示条
```

筛选胶囊里带方括号的那几个**只在有内容时才出现**。这是刻意的：空筛选器是装饰，不是控件。
所以「收件箱」胶囊看不到时，意思是收件箱是空的，不是功能没了。

## 2. 记一条

**点「＋添加」** → 输入框出现 → 写标题 → 回车或点「添加」。

- 回车保存（标题框里）。标题为空时「添加」按钮是灰的。
- **只有标题是必填**。描述、附件、步骤、标签、优先级、截止时间都在「更多字段」后面。
- 记完表单**不会自动关**，方便连着记几条。点右上角的 × 或再按一次「＋添加」收起。

「更多字段」里各项的规矩：

| 字段 | 怎么填 | 注意 |
|---|---|---|
| 描述 | 多行文本 | 无 |
| 附件 | 一行一个**绝对路径**或 URL | 相对路径会被拒；带用户名密码的 URL 也会被拒 |
| 步骤 | 一行一步 | 最多 20 步、每步 200 字；**这是交出去时那份编号计划** |
| 标签 | 逗号分隔 | 特殊标签 `inbox` / `someday` 有专用语义，见 §7 |
| 优先级 | 四档：紧急/高/一般/低 | 你设一次就锁死（`prioritySource: human`），之后规则不再覆盖 |
| 截止时间 | 日期时间选择器 | 见 §6 的「级别由截止时间算」 |

**快捷键**：`n` 开一条新待办，`/` 聚焦搜索，`Esc` 收起最内层浮层，`Enter` 在标题框里保存。

## 3. 看和改一条

**点行正文**（不是勾选框、不是按钮）展开详情卡。再点一次收起。

行上从左到右：勾选框 → 标题+标签 → 元信息（编号、级别、时间、来源）→ 附件芯片 →
「交给 Agent」→ ⋮ 菜单。

详情卡里有六到八段，按需出现的：

| 段 | 内容 | 能改吗 |
|---|---|---|
| 编辑 | 标题、优先级、截止时间、描述 | 能，改完出现「保存/取消」 |
| 会话回读 | 那个会话在跑还是休眠、它最后说的一句话、跳转按钮 | 只读 |
| 备注 | 备注列表 + 输入框 | 能加，不能改历史 |
| 证据 / 完成 | Agent 提交的完成记录和产出文件 | 只读 |
| 步骤 | 步骤清单 + 每步的勾 | **只能勾，不能改文字或增删** |
| 附件 | 每个附件 + 挂上/摘掉/改指向 | 能 |
| 最近派发 | 上次交给了谁、成败、原因 | 只读 |
| 活动 | 这条记录的操作流水 | 只读 |

**注意 §10 的第 1 条**：详情卡里的「编辑」段**不含标签和步骤**。这两个字段建完之后改不了，
只能靠批量操作或让 Agent 改。

### 行的 ⋮ 菜单

菜单里的项**随状态变化**，不是固定列表：

- `待确认` 的记录：最上面多出「确认完成 / 退回清单」
- `收件箱` 的记录：多出「确认 / 丢弃」
- 已完成的：`重新打开`；未完成的：`标记进行中`
- 已归档的：`取消归档`；否则：`归档`
- 永远有：`详情/收起`、`删除`

**删除是两步**：点「删除」→ 菜单项变成「确认删除」→ 4 秒内再点才真的删。删完底部有
「撤销」条，8 秒内可以点回来。

## 4. 交给 Agent

这是这个插件的主线。一条待办的完整交接流程：

```
你写待办(带步骤) ──> 点「交给 Agent」──> 选对话 ──> 派发 ──> 那个对话开始干活
                                                              │
                          ┌───────────────────────────────────┘
                          ▼
                    Agent 说「做完了」→ 进「待确认」→ 你点头 → 真的完成
```

### 4.1 派发

1. 鼠标移到行上（手机上是常显的），点**「交给 Agent」**。
2. 弹出「交给哪个对话」选择框，列出：
   - 你的对话（按最后使用排序，标「最近说过话」的那个是 Host 自己会选的）
   - `自动（已绑定 → 最近说过话 → 新开）`
   - `＋ 开一个新对话（在工作区）`
   - `＋ 新对话 · <工作区名>`（每个工作区一项，最多 6 个）
3. 选一个，可选勾「记住这个选择」，点**「确定交给」**。

**勾「记住这个选择」的差别**：勾了会写回工具栏的默认值，以后别的批量操作用它；不勾只影响
这一次。默认不勾。

派发中按钮显示「正在交给…」，对话框保持打开直到请求结束——所以慢的时候你看得见它在动。

派发成功后底部弹提示「已交给「对话名」——去那个对话看它的进展」，带一个跳转按钮。

### 4.2 目标选择的实际含义

| 选的是 | Host 会怎么做 |
|---|---|
| 某个具体对话 | 原样发过去（`authoritative: true`），不做任何推断 |
| `自动` | 先看这条已绑定的会话 → 再当前对话 → 最后新开 |
| `＋ 开一个新对话` | 总是新开，工作目录继承写下这条待办的对话 |
| `＋ 新对话 · 工作区` | 新开，工作目录就是你选的那个工作区 |

**找不到任何可用对话时是明确失败**（会告诉你原因），不会偷偷开一个新的。

### 4.3 工具栏那个 `交给：` 下拉

它还在，但**是面板级默认值，不是单条派发的入口**。批量分配和设置面板读它。单条派发不用先动它
——这正是 2026-11-12 那次改动的内容（见 CHANGELOG 的 Unreleased）。

### 4.4 批量分配（一次交给多条）

1. 点工具栏（手机在搜索行末尾）的「选择」进入选择模式。
2. 行左侧出现方块勾选框，勾几条。
3. 顶部出现批量条：`一键分配` / `完成` / `归档` / `移到稍后` / `加标签`。
4. 点「一键分配」。

分配策略是 Host 定的：**优先回到写下它的那个对话 → 其次同工作区的对话 → 都找不到才让你选**。
找不到的那批会单独弹一条提问，你选一个目标一起送。

## 5. 完成与「待确认」

**核心规则：Agent 说做完了不算完成。**

它自己在工具里报完成，或者交给的会话干净收尾后宿主自动收尾，都只把记录变成「已完成 + 待确认」：

- 行上出现「待确认」徽标
- 顶部出现带计数的「待确认」筛选胶囊
- 那条记录进「待确认」视图

两个动作：

| 动作 | 结果 |
|---|---|
| 确认完成 | 保持已完成，标记消失 |
| 退回清单 | 回到未完成，完成记录清空，事情继续留着 |

在「待确认」视图里可以批量确认（勾几条 → 批量条的「确认完成」）。

**你自己勾的勾选框不走这个流程**——人做的完成就是完成，没有待确认环节。

## 6. 时间、优先级、提醒

### 6.1 级别是算出来的，不是选的

| 条件 | 级别 |
|---|---|
| 已逾期 | P0 紧急 |
| 48 小时内 | P1 高 |
| 7 天内 | P2 常规 |
| 没有日期 | P3 低 |

你在详情里手动选一次优先级就**锁死**（`prioritySource: human`），之后规则不再覆盖它。详情卡里
那行小字会告诉你当前是高是低、为什么。

### 6.2 到点提醒

设置 →「到点提醒」→ 勾「开启到点提醒」，可设「提前（分钟）」。

- 到期时面板顶部出现提示条，点条目会展开那条记录。
- 可另外「开启系统通知」（要浏览器授权）。
- 通知是**记在内存里**的：重启后会重新提醒一次还没确认的到期项——这是刻意的，漏提醒比重复提醒糟。
- 改一次截止时间算一个新的提醒。

## 7. 收件箱、稍后、归档、陈旧

四个都是「不在主清单上但仍然存在」的状态，区别很重要：

| 状态 | 怎么进来的 | 怎么出去 | 占清单名额 |
|---|---|---|---|
| 收件箱 `inbox` | 外部写入、置信度低于阈值、Agent 记的**没有截止时间**的条目 | 行菜单「确认」→进清单；「丢弃」→归档 | 不占 |
| 稍后 `someday` | 只能批量「移到稍后」 | 「稍后」视图里勾选 → 批量条「提到清单」 | 不占 |
| 归档 `archived` | 行菜单「归档」、收件箱里「丢弃」 | 行菜单「取消归档」 | 不占 |
| 陈旧 `stale` | 自动判定：**三周没动且仍没完成** | 改一下它（改完就自动不算陈旧了） | 占 |

**陈旧不是判决**，是一个提问：这条还算数吗？改动任何字段都会让标记消失。

**稍后只能在「稍后」视图里拉回来**，主清单里看不到它，行的 ⋮ 菜单也没有「取消稍后」项。
这是当前设计里最容易卡住人的地方之一（见 §10）。

## 8. 搜索与筛选

### 8.1 筛选胶囊

`全部 / 未完成 / 进行中 / 已完成 / 逾期` 常驻；`归档 / 收件箱 / 待确认 / 陈旧 / 稍后`
有内容才出现。点一下切换。

筛选和搜索是**独立条件**：在「未完成」里搜「部署」，搜到的是「未完成 且 提到部署」。

### 8.2 搜索

`/` 聚焦，或直接点搜索框。输入后**回车**或**点走**才生效（不是边打边搜）——这是刻意的，
避免每敲一个字就发一次请求。

搜索范围：标题、描述、备注内容、标签。

### 8.3 分组维度

工具栏右侧三个按钮：`工作区 / 时间 / 待办等级`，默认**工作区**。

- **工作区**：同一个目录写下的待办折叠成一条（显示「N 条」），组头是目录名，悬停看完整路径。
  没有来源目录也没有绑定会话的（面板里手加的）进「手动添加」组。
- **时间**：逾期 / 今天 / 接下来 / 以后 / 没有截止时间
- **待办等级**：按 P0–P3 分组，组头显示组内最高级别

工作区组**永不自动折叠**（它是你要的组头，折起来会藏掉大部分清单）。

## 9. 其余入口

| 位置 | 功能 | 说明 |
|---|---|---|
| 齿轮 / ⋮→设置 | 设置卡 | 见下 |
| ⋮→本周报告 | 周报卡 | 近 7 天完成了几条、涉及几个会话、新增几条、触及哪些文件 |
| ⋮→刷新 | 立即重读 | 面板本来每 20 秒自己刷一次 |
| ⋮→导出 / 导出 Markdown | 存文件 | 见 §11 |
| ⋮→导入 | 从 JSON 文件 | **合并**（同 id 覆盖、新 id 追加），不删除现有 |
| ⋮→快捷键 | 快捷键卡 | |
| 分组头 ⋮ | 从本对话抓取 / 本工作区免打扰 | 见 §9.2 |

### 9.1 设置卡的各项

| 项 | 作用 | 生效方式 |
|---|---|---|
| 清单预算 · 未完成上限 | 最多几条未完成，满了新记录进收件箱。默认 20，0 = 不限 | 点「保存」 |
| 抓取权重 · 低于此权重不登记 | 批量抓取时跳过低于这个权重的条目。默认 0.35 | 点「保存」 |
| 到点提醒 | 开关 + 提前分钟 | 点「保存」 |
| 自动获取 | 开关 | **立刻生效，不用保存** |
| 安静窗口（分钟） | 自动获取的静默门槛，5–1440 | 失焦即写 |
| 外部接入 ingest | 开关 + 访问 token + 置信度阈值 | 点「保存」 |
| 多端同步 | 共享目录 + 同步间隔 + 「立即同步」 | 点「保存」 |
| 关于 | 数据文件路径、版本 | 只读 |
| 存储文件路径 | 只读 | |

**这是一处反人类的地方**：同一个设置卡里，有的项要「保存」才生效，有的项（自动获取开关、
安静窗口）立刻生效。见 §10。

### 9.2 从对话抓取

想让某个对话自己把该跟进的事整理成待办：

1. 找到那个对话所在的分组头（按工作区分组时）。
2. 点组头右侧的 ⋮ → 「从本对话抓取」。
3. 面板往那个对话里注入一句提示，Agent 用 `global_todo_capture` 抓取。
4. 结果进清单（权重够的话）或收件箱。

只对**当前分组绑定到某个会话**时可用；纯目录分组没有这一项。

### 9.3 本工作区免打扰

同样的组头 ⋮ →「本工作区免打扰」：这个目录下的对话**永不自动获取**。再点一次取消。
免打扰的分组头上有个小喇叭斜线图标。

## 10. 让 Agent 操作

这些不是面板上的按钮，是在对话里让 Agent 做的事。工具共 11 个：

| 工具 | 用途 |
|---|---|
| `global_todo_add` | 新增一条 |
| `global_todo_capture` | 从**当前对话**里批量抓取该跟进的事 |
| `global_todo_list` | 列清单（可按状态/标签/关键词筛） |
| `global_todo_get` | 读一条的完整内容 |
| `global_todo_update` | 改标题/描述/标签/步骤/截止/优先级 |
| `global_todo_link` | 挂上或摘掉附件 |
| `global_todo_note` | 追加一条进展备注 |
| `global_todo_done` | 声明完成（**进待确认，不是真完成**） |
| `global_todo_reopen` | 标回未完成 |
| `global_todo_remove` | 删除（留墓碑） |
| `global_todo_sync` | 立刻与共享目录折一次 |

自然语言的说法：「抓一下待办」「记一条：×」「把 #42 标完成」「看看清单上还有什么」。

**Agent 改不了的两件事**：它不能替你确认完成（那是人的动作），它也不能改归档策略。

## 11. 数据与备份

| 东西 | 位置 |
|---|---|
| 清单 | `$DSH_HOME/global-todo/todos.json`（默认 `~/.dsh/global-todo/todos.json`） |
| 宿主侧设置 | 同目录 `settings.json` |
| 面板错误日志 | 同目录 `client-errors.log` |

写入是「临时文件 + rename」，所以直接 `cp` 那个 json 拿到的一定是完整的一份。

| 方式 | 适合 |
|---|---|
| 复制文件 | 快照、放进同步盘 |
| ⋮→导出 JSON | 需要导回去（面板导入是合并；API 传 `mode: 'replace'` 是精确还原） |
| ⋮→导出 Markdown | 要读、要 diff、要贴笔记（导入时只新增，不覆盖） |

**两台机器共用一份清单**：不要共享同一个 `storePath`（每次读都走网络，断网就打不开）。用
设置 →多端同步，两边填同一个绝对路径，各自留本地文件、在那个目录里折成一份。按记录合并：
同一条看 `updatedAt`，删除留墓碑，另一台的旧副本不会带回删除。间隔填 0 就只手动同步。

## 12. 手机上的差异

面板宽度 ≤ 600px 时切成触摸布局，以下几点和桌面**不一样**：

- 「交给：」「上下文」「自动获取」从工具栏**移进设置卡**（手机上这三行会挤掉整个首屏）。
- 行上的「交给 Agent」收成图标。
- 按钮、输入框、筛选胶囊都是 44px 触控目标。
- 筛选胶囊横向可滑，不折行。
- 往下滚动时搜索行会折叠，向上滑回来。
- 所有对话框/菜单满宽。

## 13. 状态与它对应的界面

排查问题时的对照表：

| 你看到的 | 意味着 |
|---|---|
| 行是绿的、带「待确认」 | Agent 报了完成，等你点头 |
| 行有红色「逾期」+ P0 | 过了截止时间 |
| 行有「上次派发失败」红芯片 | 上次交给 Agent 失败了，悬停看原因 |
| 行有「步骤 1/5」 | 有步骤清单，详情里能勾 |
| 分组头有小绿点 | 那个工作区里有会话在跑 |
| 分组头有斜线喇叭 | 这个工作区免打扰 |
| 底部提示条「清单已满」 | 未完成数到头了，新记录进收件箱 |
| 顶部红色横幅 | 某个请求失败了，带「重试」 |

## 附：Agent 侧的完整字段

给 Agent 写指令时可能需要知道字段名。完整模型见 [DESIGN.md](DESIGN.md)，这里只列用户会碰到的：

```
id           稳定 id（工具用）
seq          人读编号，显示成 #42
title        标题
description  描述
status       open | doing | done | cancelled | archived
priority     urgent | high | normal | low
dueAt        ISO 时间或 null
tags         字符串数组；inbox / someday 有专用语义
steps        [{ text, done }]，最多 20 条
links        [{ kind: 'url'|'file'|'image', value, title }]
notes        [{ at, by, text }]，只增不改
sessionId    绑定的会话（派发后才有）
lastDispatch { ok, at, error, sessionId }
review       { pending, ... } 待确认状态
trash        墓碑 [{ id, at, by }]
```

# 附二：已知的反人类之处

下面是通读源码 + 实际操作后整理的清单，按「卡住人的程度」排序。**每一条都是现状，不是
指责**——有些是刻意的取舍，有些是漏掉了。标了类型的区别在此：`[设计取舍]` 是有理由但代价
真实存在，`[缺陷]` 是没理由、应该改。

## A. 会让人卡住的

### A1. 单条待办改不了标签和步骤 `[缺陷]`

详情卡的「编辑」段只有**标题、优先级、截止时间、描述**四项。标签和步骤在建完之后**没有任何
界面入口**：

- 标签只能靠批量条（选择模式 → 勾选 → 「加标签」），一次加一个，且**不能删**。
- 步骤只能勾选完成状态，**不能改文字、不能增删**。

后端 `/update` 完全支持这两个字段（`service.update` 会走 `applyPatch`），Agent 也能改。纯属
界面没做。

**绕法**：让 Agent 改（"把 #42 的步骤改成…"），或者删掉重建。

### A2. 「稍后」只能批量拉回来 `[缺陷]`

「移到稍后」只在批量条里（选择模式 → 勾选 → 「移到稍后」），行的 ⋮ 菜单里没有。更麻烦的是
拉回来：只能在「稍后」视图里勾选 → 批量条「提到清单」。而「稍后」筛选胶囊**只在有内容时才
出现**（见 §1 的规则），所以：

- 只有一条被移到稍后时，胶囊出现，还能找到；
- 但单条操作完全没有入口——为了还原一条，必须进入选择模式勾它。

单条 park/unpark 是个明显的缺口。

### A3. `n` 快捷键在没打开表单时什么都不做 `[缺陷]`

快捷键说明里写「`n` 开始记一条」，实际实现是 `titleRef.current?.focus()`。而 `titleRef` 只在
「＋添加」展开后才挂载。所以：

- 表单没开时按 `n`：**毫无反应**（`titleRef.current` 是 null）。
- 表单已开时按 `n`：光标跳到标题框。

它没有先 `setAdding(true)`。正确的行为应该是「没开就开并聚焦，开了就聚焦」。

### A4. 搜索不是边打边搜 `[设计取舍]`

输入框 `onChange` 只更新本地状态，**回车或失焦**才真正查询。防的是每敲一个字发一次请求。
代价是：打完字以为在搜，其实没搜；必须想到按回车或点别处。

### A5. 设置卡里一半要保存、一半立刻生效 `[缺陷]`

同一个设置卡：

- **立刻生效**：自动获取开关、安静窗口（分钟）
- **要按「保存」**：到点提醒、提前分钟、清单预算、抓取权重、ingest、多端同步

没有任何视觉区分。改完预算没按保存就关掉，改动无声消失。代码里其实每项都有注释说清楚，
但界面上没体现——这是一致性问题，不是设计意图。

## B. 容易点错的

### B1. 选择模式里并排两个圈 `[设计取舍]`

进入选择模式后，行左侧同时出现：完成圆（24px，一直在）+ 选择方框（22px，新出现），之间只隔
10px。两个都是圆的、都带勾，一左一右。想在多选时误点完成、或者相反，是很容易的。

实测位置：方框 x=219、圆 x=251，间距 10px。

### B2. 删除是「同一个菜单项变文字」 `[设计取舍]`

点「删除」→ 菜单关闭 → 但此时菜单项已经变成「确认删除」，**必须重新打开 ⋮** 才能看到并点它。
4 秒内不点就变回「删除」。

也就是说这个"二次确认"要求你在 4 秒内做两次菜单操作。一般人的预期是弹一个确认框。

### B3. 「丢弃」和「删除」是两件事 `[设计取舍]`

- **收件箱里的「丢弃」**：状态变成 archived，记录还在，可以取消归档。
- **⋮ 菜单里的「删除」**：进 trash 墓碑，8 秒撤销窗口，之后没了。

两条路径都通向"从眼前消失"，但一个可逆一个基本不可逆，措辞上没提示区别。

### B4. 只有「删除」有撤销 `[缺陷]`

`showUndo` 只被 `remove` 调用。完成、归档、移动、批量改状态**都没有撤销**。对一条误勾的
「完成」，只能去「已完成」视图找回来再勾一下。

## C. 找不到的东西

### C1. 工具栏的 `交给：` 藏在折叠面板里 `[缺陷]`

工具栏上有一行摘要芯片（工作目录 · 交给: xxx · 上下文），点任意一个会展开 `.gt-context-details`，
真正的 `<select>` 在里面。

但实测（静态预览）：**点这三个芯片都不会展开它**——`data-open` 始终是 `0`，`select` 始终
`isVisible() === false`。代码里 `setContextOpen` 绑定在这三个按钮的 `onClick` 上，逻辑是对的；
预览是桩渲染器（点击不触发重渲染）所以测不出来。真实宿主里应该能展开，但**这个控件确实默认
不可见**，用户得先猜「上下文」这个词后面藏着交给目标。

好消息：这正是 A 之外我们刚修掉的问题——单条派发不再需要碰它。

### C2. 收件箱/稍后/归档/陈旧的关系没有一处讲清 `[设计取舍]`

四个都是"不在主清单上"，但：

| | 谁放进去 | 怎么出来 | 占名额 |
|---|---|---|---|
| 收件箱 | 外部写入 / 低置信度 / Agent 记的无截止条目 | 确认→进清单；丢弃→归档 | 不 |
| 稍后 | 只能批量 | 只能批量 | 不 |
| 归档 | 菜单 / 丢弃 | 菜单取消归档 | 不 |
| 陈旧 | 自动（21 天没动） | 改一下就没了 | 占 |

界面各处有零散提示（每个视图顶部一条 note），但没有一处把它们的关系摆在一起。文档里我补了
（§7），产品里仍然缺。

### C3. 「本周报告」实际是"最近 7 天" `[设计取舍]`

标题写「本周」，实现是 `days: 7` 的滚动窗口。周一早上打开看到的其实是上周五到本周一。措辞和
实现不一致。

## D. 小的

- **D1** 收件箱条目超过 7 天没人确认会被自动归档（宿主每 6 小时扫一次）。没有任何提示说
  「你不管它就会消失」。
- **D2** 「陈旧」是 21 天没动**且**未完成；一旦改动任何字段就重置。但界面只显示一个「陈旧」
  胶囊，不显示"还剩几天变陈旧"，也没法主动标记。
- **D3** 分组头的工作区目录名截断显示，完整路径只有悬停 tooltip——上一行摘要芯片里其实有
  完整路径，两处信息重复但用法不同。
- **D4** 批量条的项目随视图变化（待确认视图多「确认完成」、稍后视图多「提到清单」、收件箱
  视图多「确认/丢弃」），但没有一处文档或界面提示会变。
- **D5** 「一键分配」这个名字暗示一条命令全部搞定，实际可能弹第二轮让你选目标（找不到原对话
  的那批）。文案没有预告这一步。
- **D6** 优先级手动设置会锁死（`prioritySource: human`），之后截止时间再变也不影响级别。
  详情里有一行小字解释，但很容易漏读——用户会以为"我设错了改不回来"。

## 如果要动手，建议顺序

1. **A3**（`n` 快捷键）——一行改动，`setAdding(true)` 后再 focus。
2. **A1**（详情里补标签与步骤编辑）——后端已支持，只缺界面。
3. **A2**（单条 park/unpark 进 ⋮ 菜单）。
4. **B4**（给完成/归档加撤销，与删除共用 `showUndo`）。
5. **A5**（设置卡统一成"改了就生效"，或统一成"都要保存"，别混）。
6. **B2**（删除改成真正的确认框）。

前三条都影响日常使用，后三条影响的是"做错了能不能救回来"。
